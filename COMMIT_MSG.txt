Fix V14 crash, and stop this class of mistake reaching a browser again

V14 read d["hostScrollW"], which is crossclient.py's key name. check.py's
probe returns docScrollW. I wrote V14 on a machine with no browser and never
ran it, so the mistake surfaced as a KeyError on the first real run.

A KeyError is the lucky outcome. Written as d.get("hostScrollW", 0) the same
mistake would have made V14 silently never fire - a check passing because it
looked at nothing, which is the failure this repository keeps finding in
itself.

So tests/test_validation.py now reads the validation scripts without running
them, and costs nothing:

- every probe key a script reads must be one its own probe returns
- no probe key may be read with a fallback default, because a missing
  measurement would then read as a pass
- check ids must be unique and unbroken

Writing those found two bugs in the tests themselves - a regex that consumed
its own separator and so matched only every other shorthand key - and one
real gap: there is no V3 anywhere in the source or the docs. It is now
declared retired rather than left silent, and the number stays unused. An old
report and a new one would otherwise disagree about what V3 meant.

341 tests pass, up from 336. V14 and V15 still have not run here.
